# lrmame driver subset

Generated by `tools/lrmame-subset.py`. Each number is a count of driver
*files* except where it says parents.

- **752 driver files** = 728 carrying coverage + 24 pulled in only to close clone→parent links
- **2017 parent romsets** of coverage value
- **28** of the 728 coverage files are DRC-backed and all of them run on `drcbearm32`: **8** on the SH front-end it was validated against, **20** on a front-end (MIPS, PowerPC, E1-32, SHARC) nothing has checked yet
- **181** of them have a mame4all fallback if lrmame cannot hold 60 Hz; the other **547** do not

## Kept — 728 files, 2017 parents

`DRC` names the UML front-end the board needs. They all lower through the
same back-end — `drcbearm32` — because `drcuml.cpp` picks one per binary;
`sh` is the only front-end that back-end has been validated against, so a
row naming anything else is running unverified code, not slower code.

`fallback` marks a family mame4all also runs: if lrmame cannot hold 60 Hz
there, the game ships on the older engine instead of not shipping. A blank
means lrmame is the only engine that has it, so its fps number is the whole
decision.
